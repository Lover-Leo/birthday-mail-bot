# DeepSeek 邮件聊天：小鲸鱼

在已经运行生日提醒的 Google Apps Script 项目中新增 `AIMail.gs`，保留原来的生日代码和名单。

2026-10-28 新增“小鲸鱼”人格，聊天和生日提醒共用完整人设卡。已有云端项目的更新方法见 [WHALE_PERSONA.md](WHALE_PERSONA.md)；仅修改本机文件不会自动部署到 Google。

用户随后要求增加调用次数：新版已将项目每日总上限由 **10 提高到 30**，生日生成仍最多 2 次，所有成员共用。打开 `API额度更新.html` 复制新版 AIMail.gs，保存到 Google 后运行 aiMailStatus：maxCallsPerDay 应为 30，callsToday 为已用次数，remainingCallsToday 为项目内剩余次数。更新不重置今天已用次数，不改变 DeepSeek 账户余额或 Gmail 邮件额度。云端生效尚待该日志确认。

## 开放当前收件人，并给本人发送回复副本

开放后，名单成员启用后主动发送的 `[AI]` 新邮件正文及同一对话必要文字上下文会交给 DeepSeek 生成回复；对外回复同时密送一份给发件账号本人。请在明确同意此处理范围后启用。

打开本目录的 `收件人聊天更新助手.html`，复制新版代码替换 Google 项目中的 **AIMail.gs** 并保存。左侧仍选中 AIMail.gs，从顶部函数列表运行 **enableRecipientAiMail**。

- `allowedSenders` 应列出当前云端收件人和发件账号本人，`otherReplyCopyTo` 应为配置中的发件邮箱。
- 现有任务仍启用时无需重新运行 setupAiMail；若 enabled 为 false，运行 setupAiMail 即可。生日文件和触发器无需修改。
- 白名单从运行当时 Google 中的 BIRTHDAY_DATA.recipients 读取并保存。今后增删生日收件人后，重新运行 enableRecipientAiMail 才会同步聊天权限。原有成员的启用时间保留，被移除的成员不再处理。
- 此函数不发邮件、不调用 DeepSeek。新成员只处理开放后主动发来的新邮件，旧邮件正文不用于补答。新代码未运行开放函数时仍保持仅本人可用。
- 发给其他人的每封回复，通过同一次 Gmail 回复操作密送给发件账号本人，不额外调用 DeepSeek；本人自发自收测试不再密送。对外回复按 2 位收件人检查额度，不足时暂缓。

让名单成员发送一封新邮件至配置中的发件邮箱，主题含 `[AI]`，不抄送其他人。可等下一轮自动检查，也可手动运行 pollAiMail。朋友收到直接回复，本人收到密送副本。

## 安装

1. 在原项目左侧“文件”旁点击 `+` → “脚本”，命名为 `AIMail`。
2. 将本机 `cloud/AIMail.gs` 的全部内容粘贴到新文件，替换默认内容并保存。**不要替换原来的生日文件。**
3. 点击左侧“项目设置”齿轮 → “脚本属性” → “添加脚本属性”。属性名填 `DEEPSEEK_API_KEY`，值填你已有的 **DeepSeek 官方 API Key**，然后保存。密钥不需要发到聊天或写进源代码。
4. 顶部函数选择 `checkAiMailSetup`，运行并授权。它会验证当前账号、Gmail 读取权限和 DeepSeek 的模型列表，不调用聊天接口，也不发邮件。
5. 检查成功后运行 `setupAiMail`。这会创建每 5 分钟运行一次的 `pollAiMail` 触发器，不改变生日提醒触发器。状态应为 enabled=true、triggers=1（此处仅统计 AI 触发器）。

新增权限用于读取符合条件的 Gmail 测试会话以及访问 DeepSeek API。Google 的 GmailApp 权限提示可能覆盖整个邮箱，程序会按下文规则筛选。只有指定会话的文字上下文会发给 DeepSeek。

如果此前为项目显式设置了 oauthScopes，并出现缺少权限的报错，可将 `appsscript.ai.json` 的内容应用到 Google 项目的 `appsscript.json`。如果项目还配置了其他服务，应合并 scopes，保留原配置。

## 测试和继续对话

用配置中的发件邮箱给自己发送邮件，例如：

```text
收件人：your-account@gmail.com（替换为自己的发件邮箱）
主题：[AI] 测试聊天
正文：你好，请用一句话介绍你自己。
```

可以等待下一次云端检查，也可以手动运行 `pollAiMail` 立即处理。你刚发的测试邮件如在首次启用前一小时内，且主题含 `[AI]`，也会被检查。

收到回复后，直接回复同一封会话继续聊天。新开主题会被当作另一个对话。不要在输入中复制机器人的固定自动回复标记。

## 当前处理范围

- 接受白名单成员发给机器人的一对一邮件；Reply-To 若存在须与发件人相同，不处理多个收件人、抄送或可识别的密送输入。未运行开放函数时白名单仅包含本人。
- 不同提问者分别筛选上下文，即使 Gmail 将同主题邮件合并为一个会话，也不混用其问题或机器人回答。对外回复只直接发给提问者，另外密送给本人。
- 主题包含 `[AI]`，支持收件箱和已归档邮件，排除垃圾邮件和回收站。不依赖未读标记，因此自己发给自己的邮件、被免打扰规则标为已读的邮件也可以处理。
- 忽略机器人固定标记、自动回复、邮件列表以及明确的 SPF/DMARC 失败邮件，防止回复循环。
- 纯文本聊天，暂不解析附件、图片或链接内容。
- 每个会话最多取最近 6 条、合计最多 6000 字符作为上下文；一轮检查最多处理 2 个会话。连续输入多封未回复邮件时，合并上下文回答最新问题。
- 默认使用 `deepseek-flash`、非思考模式，单次输出最多 768 token，邮件正文最多 1800 字符。
- 每天北京时间聊天与生日祝福**合计最多 30 次 DeepSeek 调用**，包含失败重试；其中生日最多 2 次，按事件缓存、所有收件人复用。还受 Google 邮件额度和 DeepSeek 账户余额限制。这是调用次数上限，不是金额上限。API 按服务商用量计费。

## 聊天免打扰，生日和任务通知保留

用户要求聊天归档按需查看，生日和云端通知仍保留提醒。现有 7 封聊天已在 Gmail 中归档、标为已读并移除重要标记，标签保留；已有生日提醒及配置通知继续留在原来的收件箱，收件箱中的这两类邮件已标为重要。

后续自动规则需要先更新云端 AIMail.gs，使 aiMailQuery_ 不再限制 in:inbox；新版查询包含归档邮件，仍排除垃圾邮件和回收站。保存后运行 aiMailStatus，应看到 archiveSearchEnabled=true。权限、人格、密送副本和每日上限均保留，无需重新建立触发器。

过滤器部分已由用户提供的 Gmail 设置截图确认：聊天跳过收件箱、标为已读、不标为重要；生日和配置／运行通知只贴标签并标为重要，不自动归档或已读，无需再次导入。当前仍待 aiMailStatus 日志确认归档收信代码和每日 30 次上限已在 Google 保存。首次设置步骤保留在 gmail/聊天免打扰设置.html。

这些规则只影响本人账号的邮件分类，朋友仍正常收到机器人回复，本人的副本继续保存。设备是否推送，还受 Gmail 自身通知设置控制。

## 运行记录和故障

运行 `aiMailStatus` 查看 enabled、触发器数量、今天调用次数和上次结果。它不会显示 API Key 或邮件正文。

- `replied`：已提交的回复数量。
- `failed`：DeepSeek 请求失败，后续自动重试，每封最多自动尝试 3 次。
- `budgetSkipped`：达到调用次数或邮件额度上限，暂缓处理。
- `needsReview`：投递状态不明确或重试次数耗尽，需要检查。为避免重复发信，状态不明确时不盲目重发，会先查找会话中对应的机器人回复。

同一封问题按 Gmail 消息 ID 去重；生成成功的答案在投递前暂存在脚本属性，发送完成后只保留精简状态。30 天前的 AI 消息状态会清理，不影响生日发送记录。

DeepSeek HTTP 401 通常需要检查 API Key；402 需要检查余额。修正后可运行 `retryFailedAiMail` 重置失败问题的尝试次数，再运行 `pollAiMail`，或发送一封新的 `[AI]` 问题。重置不会清除已回复或投递状态不明确的记录，也不会重置每日调用上限。请勿将密钥贴到报错截图或聊天里。

运行 `disableAiMail` 可关闭 AI 聊天，生日提醒继续运行，仍可独立生成祝福。将 `WHALE_BIRTHDAY.useAi` 设为 false 可让生日仅使用人设备用文案。删除 `DEEPSEEK_API_KEY` 后聊天无法再调用 API，生日自动使用备用文案。
